# 订单与退款规则

## 订单状态有哪些

| 状态 | 含义 | 能否操作 |
|---|---|---|
| 正常 | 订单已生成并支付成功 | 可使用券、可取消 |
| 已取消 | 用户主动取消，或超时未支付被系统关闭 | 不可恢复，需重新下单 |

订单的**支付时间、核销时间、退款时间**都是独立字段，没发生过的操作为空，不代表异常。

## 订单超时未支付会被自动取消吗

会。平台使用**延迟队列**（Redisson 实现）在订单创建后开始倒计时，超过设定时间仍未支付则自动关闭订单并**回流库存**。所以「刚才还能买，现在没了」很可能是超时自动取消导致的，不是系统故障。

## 抢购取消后库存会回流吗

会。取消订单时释放对应的库存并更新已购集合，让其他用户能继续抢。这个过程叫**抢购取消回流**。如果取消失败（比如 Redis 操作异常），会记入**回滚失败日志**并由对账任务兜底补偿，最终保证不出现「库存被占用但没人能买」的情况。

## 怎么判断订单是不是真的失败了

不要只看「有没有看到订单」这一个现象。平台的处理逻辑是：

1. 先在 Redis 看这笔扣减**有没有流水记录**
2. 再看订单表**有没有对应订单**
3. 结合**对账状态**判断

如果扣减流水存在但订单不存在，说明还在异步处理窗口内（状态应为「处理中」），**不是失败**。只有明确收到「库存不足」「重复购买」「令牌无效」这类拒绝原因，才是真失败。

## 对账状态是什么意思

订单记录里有一个**对账状态**字段，反映这笔订单与库存扣减流水是否一致：

| 对账状态 | 含义 |
|---|---|
| 待处理 | 对账任务尚未扫描到这笔订单 |
| 异常 | 发现不一致，已记录待人工处理 |
| 不一致 | 确认两边数据冲突 |
| 一致 | 已核对通过 |

「待处理」是正常中间态，不代表出问题。

## 退款怎么处理

平台目前支持**取消未使用的订单**并回流库存。已核销（已使用）的券不支持取消。如果遇到「应该能退但退不了」的情况，通常是订单已被核销或已过活动期，建议联系客服核查订单的核销时间。退款金额按实际支付金额（payValue）计算，不按面额。
